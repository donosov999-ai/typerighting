## 🔴 Решение: один общий сертификат распространения на оба приложения

Сертификат распространения Apple — **общий на весь аккаунт** (team-wide), не на
приложение. У psygames CI на каждом релизе создаёт новый сертификат и **отзывает
старые** (KEEP=1). Пока приложение было одно — работало. Но TypeRIGHT в том же
аккаунте: если и его CI начнёт отзывать сертификаты, два приложения будут отзывать
их друг у друга на каждом релизе (ровно инцидент psygames 04.09, код 90721, но уже
между приложениями).

Правильная модель (родная для Apple): **один общий сертификат распространения**,
экспортированный в `.p12`, лежит в секрете и **импортируется** обоими CI; у каждого
приложения **свой профиль** (профили — per-app). TypeRIGHT-CI уже написан так:
только импортирует сертификат и заводит свой профиль, **чужой сертификат не трогает**
(`scripts/ios-provision-profile.py`).

➡️ Чтобы это заработало и не ломало psygames, нужно:
1. один раз создать сертификат Apple Distribution **с сохранённым приватным ключом**
   и экспортировать в `.p12` (шаг ниже) — этот `.p12` кладём в секрет **обоих** репо;
2. psygames перевести с «создавать+отзывать» на «импортировать этот же `.p12`»
   (координирую с psygames-claude-mac — это правка их пайплайна, их зона).

## Шаг 1. Завести приложение в App Store Connect (только ты)

1. https://developer.apple.com/account/resources/identifiers → **+** → App IDs → App →
   Bundle ID (Explicit) = `com.odv999.typerighting`. Capabilities по умолчанию.
2. https://appstoreconnect.apple.com → **My Apps** → **+** → New App.
   - Платформа: iOS. Имя: `TypeRIGHT`. Язык: русский. Bundle ID: из п.1.
   - SKU: любое, например `typerighting-001`.

## Шаг 2. Общий сертификат распространения → `.p12` (один раз, ты)

На Mac с Xcode:
1. Xcode → Settings → Accounts → твой Apple ID → Manage Certificates → **+** →
   **Apple Distribution**. (Если такой уже создан для psygames и приватный ключ ещё в
   Keychain — можно переиспользовать его, новый не нужен.)
2. Keychain Access → найди «Apple Distribution: …» → правой кнопкой → Export →
   формат `.p12`, задай пароль.
3. В base64: `base64 -i cert.p12 | pbcopy`.

## Шаг 3. Секреты в репозиторий (ты)

Settings → Secrets and variables → Actions репозитория **typerighting**. Секреты в
чат не носим — добавь сам, мне скажи «готово».

| секрет | что это | где взять |
|---|---|---|
| `APPLE_TEAM_ID` | Team ID (10 символов) | developer.apple.com/account → Membership |
| `APPLE_API_KEY` | содержимое ключа `.p8` целиком | тот же ключ App Store Connect API, что у psygames (`~/.sdt_secrets/AuthKey_*.p8`) |
| `APPLE_API_KEY_ID` | id ключа (10 символов) | имя файла `AuthKey_XXXXXXXXXX.p8` |
| `APPLE_API_ISSUER` | Issuer ID | App Store Connect → Users and Access → Integrations → Keys |
| `APPLE_CERTIFICATE` | общий `.p12` в base64 | из Шага 2 |
| `APPLE_CERTIFICATE_PASSWORD` | пароль от `.p12` | из Шага 2 |

API-ключ (`.p8`/`API_KEY_ID`/`ISSUER`) и `.p12` — **те же самые**, что у psygames
(один аккаунт). Team ID тоже общий.

## Шаг 4. Дальше я

1. Ставлю тег `vX.Y.Z` (версия в `package.json` + `tauri.conf.json` уникальна на
   каждую загрузку — Apple отклоняет повтор номера сборки).
2. `ios-release` видит секреты и включается: импорт сертификата → свой профиль →
   архив → `.ipa` → TestFlight → подача на внешнее ревью.
3. Проверяю по логам, что сборка прошла валидацию Apple.
4. Ты ставишь TestFlight на iPad, подключаешь Bluetooth-клавиатуру — тренажёр в
   полном режиме (без клавиатуры — режим-компаньон, как на телефоне).

## Что скорее всего спросит ревью Apple

- **Назначение.** Тренажёр печати, не медицина: в описании нельзя обещать лечение
  или медицинский эффект памяти (дело FTC против Lumosity, 2016). Формулировки держим
  в этом духе.
- **Возрастной рейтинг** 4+ подходит: ни рекламы, ни азартных механик.
- **Учётка для проверки.** Вход не обязателен — дадим профиль без пароля.
- **Экспортное шифрование** — ответ «нет» уже зашит в Info.plist патч-скриптом.
